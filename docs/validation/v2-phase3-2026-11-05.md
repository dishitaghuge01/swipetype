## Overlay shortcut fix and live setup

Observed configuration before the change:

- Core daemon already ran as a user service; Super+Ctrl+Space called its CLI.
- Super+Shift+K called `gapplication action ... toggle-overlay` directly.
- No overlay service or session-bus owner was present. A terminal-launched overlay
  is a separate process from the daemon and makes its action available only
  while running. On this GLib setup `gapplication list-actions` also requires a
  desktop entry; none was installed in the checkout setup.

Implemented:

- `cli/swipetype_overlay_toggle.py` queries the session-bus name. If absent it
  starts `swipetype-overlay.service`; a cold shortcut requests `--show`, a warm
  shortcut `--toggle`.
- Host handles command lines through the existing single GApplication identity.
  Actions wait for the authoritative daemon snapshot, preventing a cold swipe
  request from being mistaken for idle layout editing or hiding immediately.
- Idle requests still enter/exit layout mode. If the daemon is absent, a
  2.5-second fallback permits layout editing. Disabled config remains respected.
- Checkout and packaged overlay units use `Type=dbus`, restart on failure and
  attach to the graphical session. The packaged core unit does not force
  Wayland or assume a distribution-specific ydotool service.
